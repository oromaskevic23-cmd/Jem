## What was actually coded

- `video/character-lock.mjs` — versioned seven-trait Character Bible, SHA-256 integrity checks, fixed source image hashes, exact characters/project scopes, immutable visual attributes, constrained change list and Ed25519-signed independent **human** review. The output is a review record **never release authority**.
- `video/ltx-offline-worker.mjs` — opt-in adapter calling the **official LTX-Video local Python inference** in a pinned manually installed checkout. Verifies Python and code paths, Git revision, script and pipeline YAML digests, full checkpoint SHA-256 with a **bounded 1 MiB buffer**, one explicit on-disk reference file and image hash, then launches `python inference.py` *without a shell*. Its output is video encoded with FFmpeg and sent to the existing `SceneReviewQueue`, which verifies H.264, size, frames, duration and local artifact path. Even a valid clip stays REVIEW_REQUIRED until independent visual QA.
- `video/cinema-session.mjs` — binds the Character Bible **before** the existing SQLite admission queue; persists a scoped evidence dossier.
- `video/cinema-cli.mjs` — manually invoked local CLI for a request JSON, independent character Bible and optional local runtime config. No payment, signup, publication or network API.
- `benchmarks/film-benchmark-v1.json` — 20 original scenario ideas with six-act targets, specified rubric and empty evidence/score fields. **No competitor or Jem benchmark outputs have been measured.**
- Negative/positive test cases for forgery, substitutions, unintended authorization, unpinned code and checkpoint changes, interrupted scene jobs, and loss of local inference.

## Model candidate selection for 8 GB RTX 2070 SUPER

**Preferred experiment:** LTX-Video `ltxv-2b-0.9.8-distilled` — official model lists a 2B distilled image-to-video config and supports `conditioning_media_paths` with `conditioning_start_frames 0`, `num_frames`, `frame_rate`, and `output_path` as an output directory. The model internally expects `8n + 1` frames; Jem requests that length, then trims to the exact target film frame count for FFprobe QA.

Sources (official):
- https://github.com/Lightricks/LTX-Video/blob/main/README.md
- https://huggingface.co/Lightricks/LTX-Video
- https://github.com/Lightricks/LTX-Video/blob/main/inference.py

**Important:** Source code and checkpoint licenses differ; check the **exact checkpoint-specific model license** before declaring commercial use. A `licenseReviewed:true` flag records an operator's assertion, not independent legal verification. The model requires a sufficiently large local GPU/CPU memory budget; official descriptions of lighter VRAM usage **do not prove** operation on RTX 2070 SUPER 8GB. This hardware was not available to the current GitHub Actions jobs.

Wan2.1 `T2V-1.3B` is *text-to-video*, not a drop-in reference-preserving I2V replacement, and official documentation describes roughly **8.19 GB VRAM** in its baseline configuration. Wan2.1 I2V-14B and LTX-2 are not established compatible with the owner's 8 GB GPU. **Do not substitute models or claim an inference success before observing actual output.** https://github.com/Wan-Video/Wan2.1

## Safe local runbook (lab only)

1. Install Node.js 22+, Python (matching official LTX dependencies), Git and free FFmpeg.
2. Independently download and verify the official LTX code **at a specific Git commit**. Only use a checkpoint with a verified compatible license. Do not blindly execute arbitrary model repositories.
3. Install dependencies in an isolated trusted local Python virtual environment; install and checksum a specific checkpoint. Run the model only on a user-authorized local machine. **Python execution is not OS-sandboxed by Jem**; a separate restricted system user/VM/container is strongly recommended.
4. Outside Git, create `request.json` matching `jem_scene_generation_request_v1` and `bible.json` matching `jem_character_bible_v1`. The Bible must be generated by the CharacterLock module and include `bibleSha256`. Source images must stay local.
5. Optional `ltx-runtime.json` must live OUTSIDE the repository and list `modelManifest`, `repoRoot`, `repoCommitSha` (40-hex), `inferenceSha256` (64-hex), `configRelativePath`, `configSha256`, `checkpointFile`, `pythonExecutable`, `referenceFiles` keyed by reference ID with absolute path + SHA-256, `artifactRoot`, and `operatorApproved:true`. Model manifest requires matching id, real weights sha and separately reviewed licensing flags.
6. Preflight without a model:

```bash
node --experimental-sqlite video/cinema-cli.mjs \
  --request ./private/request.json \
  --bible ./private/bible.json \
  --out ./private/cinema-output
```

Expected: **BLOCKED_MODEL_NOT_AVAILABLE**, a local proof JSON and no film. A blocked run may exit with code 2. A lack of available GPU does **not** change this to success.

7. Explicitly authorized local inference attempt with a manually installed model:

```bash
node --experimental-sqlite video/cinema-cli.mjs \
  --request ./private/request.json \
  --bible ./private/bible.json \
  --out ./private/cinema-output \
  --config ./private/ltx-runtime.json \
  --execute-local-inference yes
```

No model weights are shipped by Jem or installed automatically. `HF_HUB_OFFLINE=1` is set by the worker to prevent accidental Hugging Face downloads during the process. **This is not a complete network sandbox**; run with host firewall/VM network restrictions if requiring true offline assurance. Inference resource demands, duration and quality remain unverified. If the checkpoint/configuration/backend mismatch, the run must refuse or return an honest error.

**Potential integration gap:** The upstream config must really load the exact pinned local checkpoint file; Jem currently hashes the configured checkpoint, but a separate manual config inspection is required to prove the YAML points to it. Do not report the model SHA as a verified inference attribution without runtime provenance.

## Independent character-quality acceptance

The approved source image, expected character Bible, model output MP4 and scene contract are separately hash-bound.

An **independent reviewer** observes seven meaningful traits: face, hair, clothing, colors, identifying marks, silhouette and style. A review is signed using an ephemeral or owner-provisioned Ed25519 visual-QA key **outside AI worker control**, cryptographically bound to the exact request, clip and Bible hashes. A mismatched signature or contradictory observation is rejected.

This mechanism verifies the *record of a human QA decision*, not that the image classifier is objectively correct. No automatic similarity metric or 95% pass rate has been established.

Do not call a rendered video a verified character-preserving film without seeing and independently evaluating its scenes. Successful signed review is **not** an owner-signed publish permit.

## Benchmark roadmap

20 original six-act prompts are provided without unauthorized owner photos, paid model calls or fake competitor scores. Future trials must supply rights-cleared reference assets, multiple human reviewers, matched video settings and independent output evidence before any superiority claim.

Proposed weighted rubric: 35% consistency, 25% motion/image quality, 15% story, 10% speech, 10% editing/recovery, 5% accepted-minute economics. These are testing weights, **not** proof Jem is better than competitors.
